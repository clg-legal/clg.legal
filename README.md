# clg.legal

Статичний сайт [Concordis Legal Group](https://clg.legal/) на **Hugo**, з керуванням контентом через **Decap CMS** і хостингом на **Netlify**.

| | |
|---|---|
| Генератор сайту | Hugo Extended `0.148.2` |
| Стилі / скрипти | SCSS і JS через Hugo Pipes (без npm) |
| CMS | Decap CMS (`/admin/`), вхід через GitHub |
| Хостинг | Netlify (збірка при кожному пуші в `main`) |
| Заявки з форм | Netlify Forms → email `office@clg.legal` |

# Для редакторів: як користуватися CMS

## Вхід

1. Відкрийте **`https://<адреса сайту>/admin/`**.
2. Натисніть **Login with GitHub** і підтвердьте доступ.

Для входу потрібен акаунт GitHub, якому власник репозиторію видав доступ **Write** (Settings → Collaborators у репозиторії `clg-legal/clg.legal`).

## Як працює публікація

- Кнопка **Publish → Publish now** одразу створює зміну в репозиторії (коміт у `main`).
- Netlify автоматично пересобирає сайт. Зміни з'являються на сайті приблизно **через 1–2 хвилини**.
- Попереднього перегляду в редакторі немає: результат видно на сайті після збірки.
- Скасувати зміну можна лише повторним редагуванням. Якщо щось пішло не так, зверніться до розробника, всі зміни зберігаються в історії git.

## Розділи адмінки

| Розділ | Що в ньому |
|---|---|
| **Блог** | Статті |
| **Категорії** | Категорії статей |
| **Сторінки практик** | Сторінки послуг (договірне право, кримінальне право тощо) |
| **Спільні блоки** | Команда, контакти (адреса, телефони, email), налаштування форм заявок |
| **Окремі сторінки** | Сторінка «Контакти»; головна: картки послуг, кейси, FAQ |

## Статті блогу

**Створити:** Блог → **New Публікація** і заповніть поля:

| Поле | Підказка |
|---|---|
| Заголовок | Назва статті |
| Slug | Адреса сторінки, **латиницею через дефіс**, наприклад `advokat-u-kyievi`. Задається один раз, для вже опублікованих статей не змінювати, інакше зміниться URL |
| Короткий опис | Показується на картці статті |
| Обкладинка | Картинка для картки та шапки статті |
| Дата публікації | За нею статті сортуються (нові першими) |
| Категорія | Вибір зі списку. Нової категорії немає в списку? Спочатку створіть її в розділі «Категорії» |
| Автор | Підпис автора |
| Чернетка | Увімкнено = стаття **не показується** на сайті. Вимкніть, коли готові опублікувати |
| SEO | Окремий заголовок, опис і картинка для пошуковиків і соцмереж (необов'язково) |
| Текст | Основний текст у редакторі |

**Текст статті:**
- Заголовки (`H2`, `H3`), жирний, списки, посилання та картинки додаються кнопками панелі.
- Картинки, додані в текст, зберігаються поруч зі статтею.
- Кнопка **«Форма зворотного звʼязку»** (у меню `+` редактора) вставляє форму заявки.

**Редагувати / видалити:** відкрийте статтю зі списку → внесіть зміни → **Publish**. Видалення: у відкритій статті Publish → **Delete entry**.

> Якщо замінити обкладинку, старий файл у папці статті залишається. Зайві картинки може прибрати розробник.

## Категорії

Розділ **Категорії → New Категорія**: назва та slug (латиницею). Після публікації категорія з'явиться у списку в статтях, і буде доступна сторінка `/category/<slug>/`.

Не змінюйте slug наявних категорій, і не видаляйте категорію, до якої прив'язані статті.

## Сторінки практик

**Редагувати:** Сторінки практик → оберіть сторінку. Блоки:
- **SEO**: заголовок і опис для Google;
- **Верхній блок**: заголовок, підзаголовок, фон;
- **Основний текст і блок «Контакт»**: абзаци, списки, картинки;
- **Кейси** та **Часті запитання**: **свої на кожній сторінці**.

**Створити нову:** Сторінки практик → **New Сторінка практики**, заповніть назву, slug і блоки. Нова сторінка не з'являється автоматично в меню чи на головній. Щоб показати її на головній, змініть одну з карток (див. нижче), а додавання в меню потребує розробника.

## Головна сторінка

**Окремі сторінки → Головна:**
- **Картки послуг**: завжди **8 карток**. Можна змінити заголовок, текст, сторінку, на яку веде картка (список усіх сторінок практик), і порядок (перетягуванням). Так можна замінити одну послугу іншою;
- **Кейси** та **Часті запитання** головної.

## Спільні блоки (діють на всьому сайті)

| Блок | Де відображається |
|---|---|
| **Команда** | Усі сторінки з каруселлю команди |
| **Контакти** | Адреса, телефони, email у шапці, підвалі та на сторінці «Контакти» |
| **Форма заявки: спільні налаштування** | Усі форми: плейсхолдери, варіанти типу особи, згода, повідомлення про успіх/помилку, посилання WhatsApp і Telegram |

Змінили номер телефону в «Контакти»: він оновиться в шапці, підвалі, на сторінці «Контакти», а посилання WhatsApp (якщо не задане вручну) формується з «Телефон 1».

> Номери та адреси, які вписані **безпосередньо в текст** сторінок чи статей, автоматично не змінюються.

## Сторінка «Контакти»

**Окремі сторінки → Сторінка «Контакти»**: заголовок, SEO, фон і тексти форми. Адреса та телефони редагуються в «Спільні блоки → Контакти».

## Заявки з форм

Заявки надходять у Netlify (**Forms → Submissions**) і на email `office@clg.legal`.

## Поради та обмеження

- Не змінюйте **slug** наявних сторінок і категорій: зламаються посилання.
- Кілька людей редагують одночасно: перед редагуванням оновіть сторінку адмінки, щоб бачити останню версію.
- У полях можна використовувати HTML-тег `<br>` для переносу рядка (де він уже використовується).
- Не бачите зміни на сайті: зачекайте 2 хвилини, потім оновіть сторінку **Ctrl+Shift+R**. Якщо не з'явилося, перевірте в Netlify (**Deploys**), чи збірка пройшла успішно.
- Не вдається увійти: перевірте, що у вашого акаунта GitHub є доступ Write до репозиторію.

# Для розробників

## Локальний запуск

Потрібен [Hugo Extended](https://gohugo.io/installation/) (перевірка: `hugo version` → має бути `extended`):

```bash
hugo server -D --disableFastRender --ignoreCache
```

**Чому саме так:** SCSS компілюється через Hugo Pipes і кешується в `resources/`. Звичайний `hugo server -D` інколи не перезбирає імпортовані файли (`components/_hero.scss` тощо), а браузер тримає старий CSS.

Якщо зміни все одно не видно:

```bash
rm -rf public resources
hugo server -D --disableFastRender --ignoreCache
```

Потім у браузері **Ctrl+Shift+R**.

Збірка для продакшену:

```bash
hugo --gc --minify
```

## Структура проєкту

```
assets/
  scss/
    base/           # змінні, reset, типографіка, утиліти
    components/     # стилі компонентів (header, hero, faq, …)
    pages/          # стилі сторінок з імпортами компонентів
  js/
    components/     # JS компонентів (кожен експортує init<Name>())
    pages/          # JS сторінок, викликають потрібні init-функції
    site.js         # завжди підключається
content/            # контент (Markdown + front matter)
data/               # спільні дані: team, contacts, contact_form
layouts/
  _default/         # baseof, service (сторінки практик), contacts
  blog/, category/  # шаблони блогу
  partials/         # одна секція = один partial
  shortcodes/       # contact-form
static/
  admin/            # Decap CMS (index.html + config.yml)
  images/           # зображення
netlify.toml        # збірка на Netlify
```

Ідея: **сторінка → layout → partials**. Кожен partial читає свій блок із front matter (`.Params.<блок>`), тому partial і його блок у `content/` змінюються разом. Додатково підключаються `styles:` / `scripts:` зі сторінки та `bodyClass:` для стилів конкретної сторінки.

## Де лежить контент

| Що | Де |
|---|---|
| Головна | `content/_index.md` |
| Сторінки практик | `content/<slug>/_index.md` (`layout: service`) |
| Статті | `content/blog/<slug>/index.md` (page bundle: картинки лежать поруч) |
| Категорії | `content/category/<slug>/_index.md` |
| Сторінка «Контакти» | `content/contacts/_index.md` |
| Команда (скрізь одна) | `data/team.yaml` |
| Адреса, телефони, email | `data/contacts.yaml` |
| Налаштування форм заявок | `data/contact_form.yaml` |

**FAQ і кейси**: свої на кожній сторінці (блоки `faq` і `casesCta` у front matter). Секція не виводиться, якщо блок відсутній.

**Додати нову сторінку практики:** найпростіше через CMS. Вручну: створити `content/<slug>/_index.md` з `layout: service`, блоками `seo`, `serviceHero`, `serviceIntro`, `casesCta`, `faq` (взяти за зразок наявну сторінку) і `bodyClass: "page-service page-<slug>"`.

**Картки послуг на головній** (`practices.items` у `content/_index.md`) ведуть на сторінку за полем `page: <slug>` (резолвиться через `site.GetPage`); `url`, запасний варіант.

## Локальна робота з CMS

У `static/admin/config.yml` увімкнено `local_backend: true` (діє лише на localhost). Запустіть у двох терміналах:

```bash
hugo server -D --disableFastRender --ignoreCache
npx decap-server
```

Відкрийте `http://localhost:1313/admin/`: вхід без авторизації, зміни пишуться прямо у файли проєкту. Після перевірки дивіться `git diff`.

Конфігурація CMS (`static/admin/config.yml`) описує колекції: `blog`, `categories`, `practices`, `shared` (дані з `data/`), `single_pages` (контакти та головна). Повторювані набори полів винесено в YAML-якорі (`&seo_fields`, `&cases_fields`, `&form_fields`, `&faq_fields`).

> Decap при збереженні перезаписує front matter файлу цілком (лапки, порядок ключів). Перший коміт після редагування сторінки може містити великий diff без змістових змін.

## Деплой і налаштування Netlify

Збірка описана в `netlify.toml`:
- прод: `hugo --gc --minify -b $URL`;
- превʼю: `-b $DEPLOY_PRIME_URL`;
- `HUGO_VERSION=0.148.2`.

`baseURL` у `hugo.toml`, `https://clg.legal/`, на Netlify перевизначається прапорцем `-b`, інакше посилання на `*.netlify.app` вели б на clg.legal (увімкнено `canonifyURLs`).

**Вхід в адмінку (OAuth):**
1. GitHub OAuth App (бажано в організації клієнта): Homepage URL: адреса сайту; Authorization callback URL: `https://api.netlify.com/auth/done`.
2. Netlify → Site configuration → Access & security → OAuth → Install provider → GitHub: вставити Client ID і Secret.
3. У `config.yml` задано `backend: github`, `repo: clg-legal/clg.legal`, `base_url: https://api.netlify.com`, `auth_endpoint: auth`.
4. Усім редакторам потрібен свій акаунт GitHub із доступом **Write** до репозиторію. Репозиторій публічний (на безкоштовному плані Netlify приватний репозиторій обмежує кількість контриб'юторів).

**Перенос домену:** Domain management → Add a domain → `clg.legal`, змінити DNS у реєстратора за інструкцією Netlify. Після цього оновити `site_url` / `display_url` у `static/admin/config.yml` і Homepage URL в OAuth App.

## Форми заявок

Два Netlify Forms, `contact` (усі форми з іменем/телефоном/типом особи) і `hero-callback` (телефон у hero). Захист від спаму: honeypot-поле `bot-field`. Відправка: `assets/js/components/form-submit.js` (fetch на `/`).

Налаштування в Netlify (поза кодом):
- Forms → **Form detection: enabled**;
- Forms → Form submission notifications → **Email notification** на `office@clg.legal`.

Форми знаходяться при деплої, тому після будь-яких змін у розмітці потрібен новий деплой. Локально (`hugo server`) відправка не працює: перевіряйте на деплої.

## SEO

Мета-дані задаються у front matter кожної сторінки (редагуються в CMS у блоці **SEO**):

```yaml
seo:
  title: "..."
  description: "..."
  ogImage: "/images/hero-person.png"
  robots: "index, follow"
```

Якщо `seo` не задано, використовуються `title`/`description` сторінки та опис сайту з `hugo.toml`.
